## Bug found & fixed

All 20 `video_id`s start with `--` (e.g. `--5A5ZCa1dE`). The model wrappers passed
`"--sample_id", sample_id` as two argv tokens, so the worker's `argparse` read the
`--`-prefixed id as another flag and failed with
`argument --sample_id: expected one argument`. This killed every clip at the SAM3 step
on the first attempt (caption + object extraction had already succeeded).

**Fix:** switched 5 call sites to the `--sample_id=<id>` equals form, which `argparse`
accepts even with leading dashes (general hardening for any dash-prefixed id):
- [segmentation_model.py:93](models/segmentation_model.py#L93), [segmentation_model.py:139](models/segmentation_model.py#L139)
- [inpainting_model.py:85](models/inpainting_model.py#L85)
- [audio_removal_model.py:105](models/audio_removal_model.py#L105), [audio_removal_model.py:141](models/audio_removal_model.py#L141)

After the fix the run completed with **0 errors**.

### Observations
- **16 of 18 discards were at `mask_check`** (mask area ≈ 0). Many target objects were
  sound sources with no clear visual to segment (e.g. "wind", "brass band", "choir",
  "cricket", "car engine"), so SAM3 couldn't produce a mask above the 0.15 gate.
- **2 discards were at `visual_removal_check`**: the object segmented fine but EffectErase
  didn't erase it cleanly enough (removal < 0.80) — "flowing water" and "train".
- **Multiple-object handling:** when GPT-4o-mini returns several sounding objects, the node
  stores the full list in `sounding_objects` but only acts on `objects[0]`
  ([nodes.py:152-155](nodes.py#L152-L155)); the rest are recorded but never removed and
  there is no fallback to a later candidate.
